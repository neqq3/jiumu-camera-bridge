# 验证记录与后续工作

截至 2026-10-11，以下是单台 A907-J 的有限时长实验，不代表全部型号或长期运行保证。

- 用普通账号密码独立登录、取得设备列表并选择设备；无需读取 APP 缓存。
- 纯 Node.js 桥接在 Linux amd64 Docker 中运行，APP 与旧 Android 桥接停止后仍取得新的音视频。
- Docker 重启后从本地配置恢复，标准 RTSP 连续解码约 12 秒；Frigate 新生成录像包含 H.264 视频与 AAC 音频。
- 2,008 个真实分片回放得到 415 个媒体帧；乱序和重复输入结果一致，另验证序号回绕和非法分片拒绝。
- 未认证 RTSP 返回 401；HA Ingress 模式的 LAN 直连及伪造转发 IP 请求被拒绝。
- 后续 AP 无账号测试：311 个 HLP 数据包重组得到 14 个视频帧和 4 个音频帧，未计入非法或丢弃包；Pillow 解码全部 14 帧 JPEG，均为 640×480。本项没有重新解码音频，也没有验证长时间 AP 运行。
- 取得同版本原厂 OTA 文件并离线解包，通过目录长度 / MD5、RBL CRC、解包长度 / FNV 检查；没有刷机。固件命令分发和认证分析见 [研究记录](research/protocol.md)。
- [本地绑定实验服务](local-binding-service.md) 已实现 HTTP 引导与 TCP 登记、challenge、单次绑定。17 组回环测试覆盖正常流程、来源/身份拒绝、拆包/异常数据、超时、重复与重启、存储故障、清理、显式启用的 P2P 初始化，以及摄像头重连时仅由认证通过的新连接替换旧会话；测试本身不访问摄像头或路由器。另使用已核验固件中的真实协议材料完成模拟客户端往返，核对 8 处固件指针。
- HLP 控制确认增加 4 组纯离线测试：单包确认丢失后的累计确认、跨序号回绕、未来/异常游标和错误来源、单包及累计确认混合且不重复计数。依据同机固件发送与接收路径修复 channel 8/10/11 的累计确认处理；合成向量不含设备凭据。
- 后续无账号真机流程成功：AP 配网、仅目标设备 DNS 引导、HTTP/TCP 本地绑定及新密码取流。初始配网清除了 P2P 参数，实验显式采用固件共享 AP 引导参数恢复 LAN 监听；不是生成新的唯一云身份。
- 新凭据在 NAS 主机取得 119 视频帧 / 132 音频帧；实际解码 30 帧 JPEG。桥接 RTSP 检出 640×480 H.264 与 8 kHz 单声道 AAC，音视频连续解码 12 秒，另解码麦克风 4 秒。Frigate 恢复实际帧率，无需改变原 RTSP 访问凭据。
- 后续将 P2P TCP 地址改为本地目标，并修复 HLP 累计确认。RTSP 音视频及麦克风再次解码通过；重启前连续三分钟的 13 次采样均收到新音视频，Frigate 持续收帧，重连计数为 0。真实身份核对后的软件重启也恢复了取流，绑定密码、token 和首次下发时间不变；启动阶段仍发生一次自动重连和 Frigate 短暂零帧，随后恢复。尚未确认所有断流触发因素，不等同于断电冷启动或长期稳定性。

后续恢复修复新增验证：

- Linux 内核状态锁排除第二写入者，工作进程被 SIGKILL 后自动释放；原密码不会再次下发。NAS 绑定容器真实崩溃后自动重启并恢复 healthy，密码、token 和首次下发时间未变。
- 原先约 6–8 秒的控制重试截止会在媒体仍到达时断开；改为 30 秒绝对截止、逐步放缓重传并合并周期保活。短时实际 RTSP 解码通过，但约四分钟后仍出现完全无入包超时，不能认定全部稳定性问题已解决。
- 该次无入包与绑定服务五分钟固定断开时间相符；已移除认证连接的固定寿命，保留 90 秒空闲、未完成阶段的绝对期限和每窗口流量上限。离线测试覆盖跨窗口持续心跳、超限拒绝及空闲退出。
- Docker 与 HAOS 选项的仅本地模式均拒绝厂商登录 / 选择接口，已有配置保持不变。在 NAS 实例开启后，两个接口实际返回 403。强制结束媒体工作进程后 Docker 自动重启，并恢复新音视频；设备配置及管理密钥未变，启动阶段发生过一次自动重连。
- NAS 的 Docker 服务为 enabled / active，两个容器设置 `unless-stopped`。未重启承载其他业务的 NAS，不能把配置检查与进程恢复称为整机冷启动验证。
- 移除五分钟硬断开后，104 次、约九分钟采样均有新音视频、重连数不变；随后继续运行仍出现一次完全无入包及绑定重新登记。已确认的生命周期问题得到修正，但长期稳定性尚未通过。新增仅含固定原因枚举和时长的绑定断线诊断，用于区分本地主动超时与对端关闭。
- 用户按键关机后，连续三次采样确认音视频不再更新、帧数固定，桥接自动重试；用户开机后本地绑定重新登记，恢复新音视频。Frigate 连续三次为 4.9 fps，实际 RTSP 音视频解码 12 秒、麦克风解码 4 秒通过。桥接和绑定容器未重启，密码、token 和首次下发时间不变；无需登录 APP 或重新配网。仅验证一次按键关机/开机，准确开机时刻及电池是否完全断开未独立记录，不能等同于完整 WAN/IPv6 隔离下的电气冷启动。

后续自然断流诊断与转码修复：

- 绑定日志区分认证新连接替换、对端关闭与服务主动超时；新增经过类型和范围验证的电量、充电、电压与登记原因字段。测试确认其他请求字段不会进入日志，并限制心跳日志频率。
- 有效视频头保留设备时间和采集帧序号。一次未主动更新服务的中断中，序号从一万多降到百位，同时绑定重新登记；短时间内再次出现序号下降。结合固件分析，这支持采集线程重新初始化或设备重启，不能单凭此字段确定硬件重启原因。计数不是 uptime，也要考虑 32 位回绕。
- APP 对照没有发现预览必须写入的“常开”设置；现有 5 秒活动保活与 APP 观察一致。固件中的 180 秒参数用于运动告警节流，没有证据可把修改它作为断流修复。
- 合成蓝色视频复现转码时间轴错误：约 6.7 秒内以约 3 fps 输入 20 张 JPEG，旧参数只输出 2 秒时间轴。移除输入 `-r` 本身仍不能保留该 multipart JPEG 时间轴；修复在解码帧到达时重新计时，再重采样为 10 fps，测试输出约 6.3 秒。依据 [FFmpeg 输入帧率语义](https://ffmpeg.org/ffmpeg.html#Video-Options)，不能将输入 `-r` 当作输出帧率约束。回归测试使用合成画面、回环 HTTP 和 FFmpeg，不访问摄像头。
- 转码修复部署后的 RTSP 音视频实际解码 12 秒、麦克风解码 4 秒通过。Frigate 连续三段新录像的视频均为 10 秒 / 100 帧，音频时长分别为 10.112、9.984、9.984 秒，最新一段实际解码 8 秒通过；这是片段时长检查，不代表测得了真实声音与动作的同步偏差。
- 网关侧两分钟被动观察仅看到目标设备广播；后续约八分钟窗口包含 DHCP 与设备广播，没有发现目标 MAC 发往公网地址的流量或 IPv6，内核丢包计数为零。观察点是主路由 LAN 接口和 PVE LAN 上联；WAN 为 PCI 直通，未在宿主直接观测。此结果支持这些窗口内的本地运行，不代表全天、所有出站路径或永久隔离。
- 已启动有时限的长时间观察，保存源音视频新鲜度、采集序号、重连次数、Frigate 帧率及仅目标 MAC 的头部计数。早期窗口已捕获自然断流，记录保留为失败诊断；主动部署后单独计时。尚未取得 24 小时稳定性通过结果，也未把转码时间轴修复当作摄像头重启原因的修复。

当前 34 项测试（19 项绑定、2 项 Linux 锁、7 项控制确认/重试、3 项运行模式、2 项媒体头、1 项真实 FFmpeg 时间轴）在无网络的 Linux 临时容器中全部通过。时间轴测试需要安装支持 lavfi 和 MJPEG 的 FFmpeg，缺失时测试失败，不静默跳过。Windows 沙箱因临时文件重命名权限拒绝而未能完成涉及原子存储的测试；这次部署验证以 Linux Docker 为准。

后续重连与停止取流对照（2026-10-12）：

- 上述新观察窗口约 35 分钟内仍发生 7 次自然重连及 7 次设备采集序号下降。失败记录保留，不因恢复到正常帧率而改记通过。
- 另定位到下游时间戳问题：保持同一 RTSP 消费连接、每 7 秒重新启动合成视频编码器，旧检测输入在约 6.7 秒内生成了 40 秒的滤镜输出；检测输入采用接收时间后，25 秒观察对应约 25 秒输出。新增真实 go2rtc / FFmpeg 回归测试通过，测试只使用合成图像和隔离回环网络，不访问摄像头。
- 接收时间仅用于 Frigate 检测输入。初次把同一参数用于直接复制录像时，实测出现时间戳警告与片段时长波动，已改为独立的同源录像输入保留原始编码时间戳。目标摄像头热更新后，三段新录像的视频均为 10 秒 / 100 帧，音频分别 10.496、9.984、9.984 秒；最新一段实际解码 8 秒，退出成功且无警告。Frigate 整体未重启。这是短时恢复检查，仍需观察自然重连后的录像。
- 完整停止媒体桥接 900 秒，绑定服务及现有网络规则保持运行。头部观察确认无媒体数据，摄像头仍在第 11 分钟左右重新登记，恢复后采集序号下降、TCP 源端口与初始序号重新开始。桥接按预定时间自动恢复。因此持续取流不是故障的必要条件；充电状态下固件仍可本地采集，此实验没有排除采集错误或固件后台任务，也没有确定电气重启原因。
- 同期主路由 LAN 与 PVE LAN 上联的约 66 分钟观察均未发现目标 MAC 发往公网地址的包或 IPv6，内核丢包为零。两接口可能观察到同一数据包，未重复累加为独立证据；PCI 直通 WAN 仍不可见，不能称为全路径外网隔离验证。

原有 34 项 Linux 测试基线外，新增 RTSP 重连时钟测试已单独通过；生成的接入配置将检测和录像输入分开。摄像头重新启动的根因仍待定位，24 小时稳定性未通过。

原始抓包、录像和认证比对数据含隐私，未随仓库提供。因此公众不能只凭本仓库独立复现这些历史真机结论。后续应补充不含私人信息的测试向量及更多型号验证。
