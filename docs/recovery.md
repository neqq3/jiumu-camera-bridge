# 启动、恢复与本地运行验证

目前为单台 A907-J 的实验部署。已验证进程异常恢复，以及一次用户按键关机/开机后的自动恢复；尚未验证完全移除供电后的电气冷启动、宿主断电或全天稳定运行。

## 已实现

- 媒体桥接与显式启用的绑定服务均使用 `restart: unless-stopped`。正常停止的容器不会因 Docker 重启自动启动；要恢复运行需执行对应 `docker compose up -d`。宿主也必须配置 Docker 随系统启动。
- Linux 绑定状态使用内核锁。并发写入者被拒绝，崩溃后锁自动释放，已保存的设备密码不会在恢复时重新生成。
- 绑定 TCP 在完整登记认证后保持连接，90 秒空闲才关闭；握手、分片和 challenge 仍有绝对期限，每五分钟最多 128 个报文 / 128 KiB。避免实验版的五分钟固定断开影响媒体会话。
- 摄像头连接丢失后自动重试；无入包 15 秒，或无新视频 / 音频 25 秒进入恢复。没有确认的控制报文保留 30 秒绝对截止时间，重传间隔逐步增至 1.5 秒。尚有未确认命令时不继续积累周期保活。
- 转码输入要求音视频同时就绪；任一轨道超过 3 秒未更新，下一次每秒检查时关闭两路 HTTP 输入，等待完整媒体恢复。短暂中断不直接重置摄像头协议会话；快照仍可独立显示新的画面。媒体健康检查同时要求音频与视频新鲜，避免只有画面时误报完全正常。
- 管理状态仅保留最近一次失败的错误类型、会话时长、帧数、协议计数和有限的确认头信息，不保存命令正文或媒体内容。
- `LOCAL_ONLY=1` 或 HAOS 的 `local_only: true` 会拒绝厂商登录和设备选择接口，同时保留已有摄像头的 LAN 取流。此开关不提供首次配网，也不代替摄像头的网络隔离。

30 秒控制截止时间是本项目的有界恢复策略，并非原厂 SDK 的精确复刻。原先按十次重传断开会在媒体仍到达时误断；真实确认曾延迟超过约 6 秒。原 SDK 使用动态重传时长，未发现相同的固定十次限制。新策略仍需长时间真机观察。

## 验收顺序

1. 基线模式先通过官方 APP 配网并绑定自己的账号，由桥接登录、选择设备并保存。保留私有配置备份，核对媒体容器启动策略、监听和实际 RTSP 音视频解码；不要求额外购买无线设备或修改路由器。
2. 单独测试桥接或绑定进程恢复，核对凭据未变、Frigate 重新收到新帧。不要为此重启承载全家网络的宿主、路由器或交换机。
3. 摄像头真正断电至少 20 秒后开机，保留 Wi-Fi 和绑定配置，**不要按复位键**。有电池的设备需要确认已关机。记录最后新帧、恢复首帧、音频恢复和 Frigate 恢复的时间。
4. 使用原有凭据完成新的媒体会话和真实解码，确认 Frigate 的音轨、录像时长及 HA 实体；在官方账号模式下独立安排有时限的长测，保留失败。软件重启与物理冷启动分别记录。
5. 如用户另选外网隔离，再单独测试仅目标设备的规则和网关观察。观察点须覆盖实际 IPv4 / IPv6 外网出口；NAS 上的局域网视频不能证明主路由没有转发其他流量。实验无账号绑定与官方账号模式的验收不能互相替代。

媒体和绑定工作进程的崩溃恢复均已实测，配置与凭据不变；媒体恢复过程中仍观察到启动阶段重连，因此不承诺瞬时恢复。路由配置与抓包不由本测试自动修改。

## 2026-10-11 关机/开机实测

用户操作电源键关机后，连续采样确认视频和音频停止更新，帧计数不变，桥接进入自动重试。用户随后开机，本地绑定重新登记，桥接使用原凭据恢复新的音视频；Frigate 连续三次采样均为 4.9 fps。实际 RTSP 的 H.264 640×480 / AAC 8 kHz 单声道音视频解码 12 秒、麦克风解码 4 秒通过。

这次恢复没有登录 APP、重新配网或重启桥接/绑定容器；密码、token 和首次下发时间保持一致。关闭期间累积的重连计数不应当作恢复后的失败次数。采样没有记录准确的物理开机时刻，因此不据此承诺开机耗时。

这是单台设备的一次按键关机/开机验证。尚未独立确认内置电池完全断开；现有单设备 IPv4 限制仍在，但完整网关 WAN/IPv6 证据、宿主重启及 24 小时稳定性仍待完成。
