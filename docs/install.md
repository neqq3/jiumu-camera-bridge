# Docker 安装

本版要求摄像头已通过九目智联完成配网并绑定自己的账号。无账号首次配对还不能用于日常安装。

在与摄像头同一局域网的 Linux 主机上取得本仓库源码，进入根目录运行：

```sh
docker compose up -d --build
docker exec jiumu-bridge cat /data/admin-token
```

打开 `http://桥接主机IP:18082`，用读取的管理密钥解锁。此密钥会持久保存，并非一次性口令。首次填写九目账号密码后选择设备，保存并等待画面、声音在线。在“生成配置”中填写桥接主机的局域网 IP，取得本地 RTSP 地址。

网页账号密码用于向厂商登录，不持久保存。设备认证信息、本地管理密钥和 RTSP 密码保存在 `data/`，备份需要按密码文件保护。RTSP 密码与九目账号密码不同。

账号接入遇到问题时：

- “无法连接厂商服务”：检查运行桥接的主机是否可以访问外网，再重试。
- “厂商未接受登录”：核对九目账号、密码和账号状态。
- “账号已登录，但设备列表获取失败”：登录阶段已完成，设备列表通道未成功；稍后重新登录，不需要重置摄像头。
- 账号无设备：先在官方 APP 绑定；个别设备连接信息不可用时会单独标记，不影响选择其他可用设备。
- IP 填写不正确：修改为摄像头的局域网 IPv4，或留空自动发现，无需再次登录。选择页停留过久会要求重新获取列表。
- “配置未能保存”：检查数据目录权限和可用空间；此前保存的连接保持不变，修复后可以重试。

账号查询和密码登录分别设置 15 秒总时限，设备列表读取另有 25 秒时限；正常完成会提前返回。网络异常时会结束等待并显示对应错误，无需重启桥接或重置摄像头。不要因设备列表为空就清除已有本地连接，先在官方 APP 确认账号绑定状态。

| 端口 | 用途 | 监听 |
| --- | --- | --- |
| 18082 | 管理页 | 局域网，管理密钥认证 |
| 18554 | RTSP | 局域网，本地取流凭据认证 |
| 18083 | 内部媒体 | 127.0.0.1 |
| 18084 | go2rtc 管理 API | 127.0.0.1 |

管理页默认 HTTP；在不可信网络上输入账号前，应通过自己配置的 HTTPS 反向代理保护浏览器到桥接这一段。不要将服务直接暴露到公网。

使用 host 网络接收 LAN 广播，不需要 privileged、USB 或蓝牙。初次无线配网另需能操作摄像头 AP / BLE 的设备，但取流主机可以有线联网。跨 VLAN、Windows Docker Desktop 广播及多摄像头并发尚未实测。

运行维护：

```sh
docker logs --tail 30 jiumu-bridge
docker restart jiumu-bridge
```

保留数据卷以在重启后恢复设备。设备重置、解绑或凭据变化后可能需要重新导入。不要为了试验无账号配对而重置正在使用的设备。

保存连接后，可在 Compose 所在目录的 `.env` 写入 `LOCAL_ONLY=1` 并执行 `docker compose up -d`，关闭厂商账号导入接口。恢复账号导入可设为 `0` 后重新创建容器；此设置不会解除摄像头的路由限制。两种模式都无需在日常启动时重新登录。参见 [启动与恢复验证](recovery.md)。

源码已在 amd64 Docker 运行过；当时因镜像源拉取问题使用了本地已有基础镜像及媒体工具。仓库默认 Dockerfile 的完整联网构建、aarch64 构建尚待验证，详见 [验证记录](validation.md)。目前只准备源码，不提供预构建镜像。

默认 Dockerfile 安装 Debian Bookworm 的 FFmpeg；已在隔离的 amd64 环境补测其 5.1.9 软件包，首次取流及音视频分别中断后的恢复均通过。该测试使用已有基础镜像，仍不能替代从零构建或 HAOS 安装验收。

若构建在 `FROM` / 下载基础镜像阶段报告 `401 Unauthorized` 或连接重置，先核对 Docker 使用的镜像源及其访问状态。这发生在桥接程序启动之前，与九目账号密码无关。不要为了安装本项目直接替换整个 NAS 的 Docker 配置；已有镜像源可能也被其他服务使用。
