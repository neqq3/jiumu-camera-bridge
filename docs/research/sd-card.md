# SD 卡配置、录像及重启行为

2026-10-12。仅针对本次 A907-J / BK7252N / 固件 21.120.101.42。以下为固件调用链和指令核验，**没有进行实体卡、拔卡、格式化或断电测试**。普通账号接入 Frigate / HA 不需要 SD 卡。

## 主要结论

- 根目录 `product_test.txt` 与 `/sd/video` 录像文件可以共存；配置文件的存在本身不是停止录像条件。
- **当前 HLP 桥接连接与摄像头卡录像互斥。** 固件只要发现 SDK/P2P 会话，就拒绝新开卡录像，并停止已开始的写卡；局域网直连同样受限。这不影响 Frigate 在服务器上录像。
- 测试模式仍启动持续录像线程，但录像还需要已绑定、卡挂载、无相关客户端会话、电源状态允许等条件。不能承诺放入配置文件之后所有录像功能不变。
- 拔卡不立即退出已激活的测试模式。同次运行再插卡不会重读配置文件；真正冷启动要另外判断卡文件和持久设置。
- 文件本身的测试参数与服务器后来下发的永久参数是两回事，不能把“拔卡重启”当作恢复全部原设置的操作。

## 配置文件能做什么

`/sd/product_test.txt` 实际按 JSON 解析。必填字段为 `ssid`、`pwd`、`server_ip`、`server_port`、`userId`；可选 `liveVideoSwitch`、`autoWriteVuid`。这不是 shell 脚本，也不是重新刷写固件。

文件解析进入工厂测试模式，连接指定 Wi-Fi，再尝试连接指定业务 TCP 服务器。模式会改变通常的告警发送、休眠和关机路径。文件并不是任意设置都能写的通用接口，且 `server_ip` 走数字 IP 解析，不能把域名直接当作等价输入。

解析路径将参数存入 RAM，没有直接把这份测试配置全部写入 NVS。但所连接的业务服务器能够发送另一条参数命令，把服务器目标、部分身份和认证参数写入非易失存储。具体字段独立处理，因此存在只改业务目标、不改设备身份的研究空间，尚未实测其持久性和常规云引导覆盖行为。

`autoWriteVuid=0` 只是上报给服务器的请求标志，写参数处理器不检查它，不能把它视为设备端的禁止身份写入开关。后续本地服务应明确禁止无关身份变更，并保存实际修改字段的原值。

## 重启、拔卡及异常情况

下表为静态分析预期，不能代替真机结果。

| 场景 | 代码所支持的结论 |
| --- | --- |
| 不放配置文件，正常插卡 | 走普通存储和录像流程；不触发这个测试入口 |
| 尚未进测试模式，插入合法配置卡 | 挂载后尝试加载；原业务 TCP 若已初始化，会直接跳过重新初始化，不能仅凭文件被读就判定成功改向 |
| 成功进入后拔卡 | 卸载存储，不清测试标志或已读参数；不能继续向拔出的卡录像 |
| 拔下改文件，再插回，同次运行 | 重新挂载，但测试标志已经为 1，会跳过配置文件检查 |
| 删除文件而不真正重启 | 不会立即退出测试模式；没有发现持续监听文件变化的逻辑 |
| 留文件完整重新启动 | 启动代码会清除测试 RAM 并重新触发卡扫描；常规网络启动早于卡检测，仍需确认实际连接目标 |
| 拔卡或删文件后冷启动 | 不再从文件进入测试模式；按已保存配置启动，服务器此前写入的永久改变仍在 |
| 只按开关键或休眠唤醒 | 不一定完成 RAM 重新初始化，且测试模式改变部分电源行为，不能等同冷启动 |
| Wi-Fi 密码错误 | 测试标志已先置位，随后等待联网；该等待路径没有找到有界回退 |
| 本地服务器暂时不可达 | 初始化等待可返回失败，后台 TCP 仍会继续重试；不等于退出测试模式 |
| 格式化卡 | 重建整卡文件系统，录像和配置文件都会消失；本次运行的测试标志不会因此自动清除 |

完整启动入口已确认会清零覆盖测试配置与标志的 RAM，并初始化卡检测状态使带卡时重新扫描；这不能外推为每次按键关机、睡眠或低功耗唤醒都走了完整启动。尚未做实体卡重启实测。

## 录像是否仍然可用

持续录像和事件录像共用写卡函数；文件按日期保存为 `/sd/video/YYYY-MM-DD/HHMMSS.avi`。正常停止时回填 AVI 头并更新索引。

| 条件/功能 | 当前固件行为 |
| --- | --- |
| 配置文件与录像文件在同一卡上 | 路径不同，可以共存 |
| 使用现有 HLP 桥接持续取流 | 会占 SDK/P2P 会话，阻止卡录像；不区分公网和局域网，也不要求已经打开视频 |
| 断开相关会话，持续录像模式 | 录像调度在约 10 秒等待后可再次尝试；仍须满足绑定、电量、挂载等条件 |
| 未绑定设备仅放配置文件 | 文件解析不会设置 `bindFlag`，不能据此保证开始录像 |
| 工厂测试模式 | 持续录像线程仍初始化；普通休眠唤醒事件路径有变化，需要分模式实测 |
| 关闭 `humanDetection` / `alarmEnable` | 会抑制摄像头运动事件卡录像；持续录像不受这个特定开关阻止，但受其他条件限制 |
| 循环覆盖 | 清理 `/sd/video` 中最旧日期目录，保留根目录配置文件；可能一次删除整日录像 |
| 录像中硬拔卡或掉电 | 当前段的 AVI 头和索引可能来不及完成，不能保证最后一段完整 |

另有音频录制开关、日期/事件索引、回放、下载和删除录像能力。桥接尚未因此自动具备这些用户界面。多机型 APP 的菜单和字符串不能证明本机支持任意录像计划、手动卡录或任意容量；卡容量和 exFAT 兼容性仍需核验。

## 保留双录可能的另一条取流路线

业务 TCP 的直播路径与当前 HLP 会话不同：event 18 可控制 event 13 JPEG / event 14 音频发送。其标志不在 SDK/P2P 会话表中；图像及音频线程中，业务 TCP 发送与 SD 写入分别被调用，没有两者只能选一的分支。

因此，在已绑定、持续录像启用、无 HLP/P2P 或其他相关本地流会话等条件下，**改为从本地业务服务器接收媒体，有望保留摄像头 SD 录像**。这需要实现另一条取流路径，并验证吞吐、同步发送阻塞、服务器断线和写卡效果；当前只属于有代码依据的候选，尚未实现或真机双录成功，也不自动代表全部连接离云。

## SD 的其他入口

挂载时还会先扫描匹配型号/版本命名的固件升级文件，再判断是否读测试配置。升级入口与普通 txt 配置是两种能力；本次没有触发升级。配置实验卡不应混入升级文件。
