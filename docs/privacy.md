# 数据去向

用户可以选择保留厂商服务，或在验证后仅本地使用。当前已实现账号导入与局域网桥接；无账号本地绑定也在单台真机上取得音视频并恢复 Frigate，仍是实验流程。完整外网隔离仍需验证。三条路径及模式切换限制见 [选择接入方式](connection-modes.md)，不能把保留厂商联网的共存模式标为离云。

| 阶段 | 桥接访问对象 | 保存内容 |
| --- | --- | --- |
| 用户主动登录、导入设备 | 厂商 HTTPS API 与 MQTT TLS 设备服务 | 不持久保存账号密码和云 token；候选设备短暂保留内存 |
| 保存设备后取流、重连 | 摄像头的 LAN 地址与局域网广播 | 设备 ID、设备密码、协议参数、可选 IP、本地管理和 RTSP 凭据 |
| 用户打开画面 | 本地桥接、Frigate 或 HA | 录像由用户的 Frigate / HA 配置决定 |
| 用户选择实验性无账号绑定 | 自有 HTTP/TCP 服务及摄像头局域网地址 | 本地所有者编号、设备 code/token、新设备密码和协议材料；不需要云账号 |

厂商账号导入接口为 `api-gateway-1.eye4cloud.com:443` 和 `app-mqtt-gateway-1.eye4cloud.com:8883`。服务会获知登录及设备列表请求，不能把这一流程称为完全离云。

已保存连接后可设置 Docker 的 `LOCAL_ONLY=1`，或 HAOS 的 `local_only: true`。该模式在服务端拒绝厂商登录和设备选择接口，网页也隐藏登录入口；已有凭据继续用于 LAN 连接。它不修改摄像头固件、DNS 或路由，不构成摄像头已隔离外网的证据。

桥接的日常取流实现使用局域网，不包含遥测、上传录像或厂商公网转发实现。**这不等于摄像头原厂固件停止访问互联网。** 早先无账号实验结果不能直接套用于官方账号配置。2026-10-12 的官方账号模式测试中，仅启用单摄像头外网阻断后，本地音视频也中断；恢复原规则后自动恢复。因此不能将“账号导入后直接断外网”列为可用的隐私方案。

2026-10-13 的后续真机测试保留原账号设备身份和密码，把业务连接及 SDK 服务器地址分别移到自有本地服务，再保持单摄像头 IPv4 外网阻断。五分钟内 60 次音视频检查均正常、没有新增重连，新录像 H.264/AAC 实际解码通过；撤掉地址下发策略后，电源键关机开机仍自动连接本地服务、恢复 Frigate。对应网关 LAN 侧观察未见公网流量。这是单机短时及一次关机开机的可用结果，尚未证明无需网络限制、全部 IPv6 路径或长期运行。具体过程与边界见 [本地服务](local-binding-service.md)。

## 官方 APP 是另一条出网通道

只限制摄像头的外网，不限制手机或工控机上的官方 APP。APP 能在局域网取得图像后，仍可通过自己的 IPv4、IPv6 或移动网络访问厂商。因此“摄像头已经隔离”不能自动推导出“官方 APP 也不会发送用户数据”。

2026-10-13 对九目智联 1.0.12 的限时观察确认了厂商统计上报：`bpr.eye4cloud.com/burPoint/batchAdd` 发送压缩 JSON，解开后包含页面、操作事件、型号、版本及标识等字段；字段存在不代表每个字段都有有效值。还观察到厂商业务接口和公网连接。一次有效的 60 秒预览取得约 5.8 MB 局域网数据，期间测试了普通拍照，本地相册提示保存成功；已观察的请求及上传函数未发现媒体上传。但这不是覆盖所有功能、延迟上传、第三方 SDK 或后续版本的保证。

APP 缩略图更新的已跟踪路径更新本地 `FileImage` 和显示缓存。代码另有预置位 JPEG 上传、头像和日志上传功能，不能把所有上传调用都当成自动上传摄像头画面，也不能承诺 APP 从不上传图片。详细边界见 [APP 外联观察](research/privacy-controls.md#官方-app-外联与图片上传)。

隐私优先时，日常预览使用自己的 HA/Frigate；账号导入后的桥接取流不需要官方 APP 运行。若仍使用官方 APP，需把它的联网权限和媒体处理一并纳入隐私方案，不能只依赖摄像头 IP 的阻断规则。

## 关闭上传与关闭厂商远程访问

人在外面仍能通过官方 APP 观看，说明设备仍有远程观看通道。可能是经厂商协调建立的手机与摄像头 P2P 直连，也可能经过中继；仅凭“能看”不能判断本次采用哪条路径，更不能推断厂商一直在存储录像。但关闭云录像或自动告警上传，不会自动撤销这个通道。

这版固件中至少要分别处理三条媒体路径：

| 路径 | 已定位行为 | 关闭告警上报 `isReport` 是否覆盖 |
| --- | --- | --- |
| 自动告警 | 本地触发后发送事件信息、JPEG、可选音视频 | 门控新告警；不是已完成真机验证的全局隐私功能 |
| SDK/P2P 预览 | 认证会话通过 livestream/audiostream 命令取流，本地与远程共用 SDK | 不覆盖 |
| 业务服务器控制的直播 | 已建立业务 TCP 内事件 18 可控制 JPEG/音频发送 | 不覆盖；静态可达不代表已观察到厂商实际使用 |

目标“只允许自己的 HA/Frigate 取流”还需阻止厂商远程建连、中继和业务直播控制，同时保留所需 LAN 通道。不能直接关闭整个 P2P SDK，因为当前局域网桥接也依赖它。已研究过修改 SDK 的服务地址并维持 LAN 连接；这不覆盖独立业务 TCP，也不构成已交付的全部媒体隔离方案。

验收必须包括：退出现有远程会话后，手机关闭家庭 Wi-Fi、通过移动网络尝试官方 APP 新建预览；同时检查本地 HA/Frigate 继续取得新帧，再检查重启后行为。APP 预览失败只证明这次正常观看失败，不能单独证明所有数据都不外发；还需核对实际出站媒体和其他远程入口。若用户通过自己的 VPN 等方式远程访问 HA/Frigate，应与厂商远程访问分开处理。

这些网络和协议验证不需要 SD 卡。实体卡仅用于验证相机卡录像与卡配置入口；未插卡不能把“SD 事件录像仍可用”标为实测通过。开关细节见 [隐私开关研究](research/privacy-controls.md)。

数据卷、配置备份、导出的 RTSP URL 都包含敏感信息。不要上传到 issue、论坛或仓库。诊断时只分享经过检查的错误类型、型号、版本和统计数；不要公开原始抓包或手机 APP 缓存。

测试设备当前保留原官方账号身份，使用本地业务服务和本地 SDK 地址；仅该摄像头的引导 DNS 定向与 IPv4 外网限制已启用，其他规则未变。此前单独阻断的失败与回退记录保留，不能将它与此次改向后的结果混淆。固件仍包含厂商连接代码，本地接管不会自动删除这些代码；目前不承诺关闭路由器限制后仍无外联。账号辅助导入和无账号路线都需分别验证网络隔离、完整冷启动和长期恢复。进展见 [本地配对](research/protocol.md)。
